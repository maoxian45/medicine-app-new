## 每个人具体做什么

文件路径从项目根目录算。药品编辑和重新核对、儿童历史补录、新风险规则先由 sjw、qhy、wzy 定好字段，wmx 按更新后的前端接口说明接页面。

### wmx

1. 改**家庭用户 UI 包**的 `frontend-web/src/views/Medicines.vue`，让用户能改药名、成分和使用者，改完可重新核对并检查风险；库存、位置沿用现有编辑入口。
2. 改**家庭用户 UI 包**的 `frontend-web/src/views/Records.vue`，让用户填写儿童实际服药时间并提交。
3. 改**知识库管理 UI 包**的 `frontend-web/src/views/Admin.vue`，加食物饮品和特殊人群规则的录入；改家庭端 `frontend-web/src/views/Risks.vue`，展示这两类风险。大模型继续用管理端已有配置页。

### sjw

1. 在**控制包**对接药品编辑、风险预查和儿童补录，入口分别是 `backend/routers/medicines.py`、`backend/routers/knowledge.py` 和 `backend/routers/records.py`。沿用现有接口，按需要调整参数和响应。把变动的字段写进 `frontend-web/README.md` 的接口表。
2. 在 `backend/tests/test_medicine_contract.py`、`backend/tests/test_records_api.py` 和 `backend/tests/test_knowledge_features.py` 补药品编辑、儿童补录和新风险规则的接口用例。
3. 在团队的**系统测试 Word 文档**写并执行登录与权限、成员、说明书识别、老人模式、知识查询和 AI 的用例，最后汇总 wzy 的部分。

### qhy

1. 改**服务包**的 `backend/services/medicines.py` 和 `backend/services/knowledge.py`。只改库存或位置时保留原核对状态；改药名、成分或使用者时重新核对，风险检查排除正在编辑的药品。
2. 改**服务包**的 `backend/services/records.py`，处理儿童实际服药时间的校验和日期查询。
3. 改**服务包**的 `backend/services/knowledge.py`，根据药品给出食物饮品风险提示，根据现有成员资料匹配特殊人群规则。
4. 选择一个大模型，用现有管理端配置接入用药知识助手。模型需要兼容 `backend/services/ai.py` 已支持的接口。

### wzy

1. 改**实体包、数据访问包**的 `backend/models/medicines.py`、`backend/models/knowledge.py`、`backend/repositories/medicines.py` 和 `backend/repositories/knowledge.py`，支持编辑字段、排除当前药品和一起保存药品及核对结果。
2. 改**实体包、数据访问包**的 `backend/models/records.py` 和 `backend/repositories/records.py`，用已有的 `taken_at` 存实际服药时间，`created_at` 存提交时间。
3. 在 `backend/models/knowledge.py` 和 `backend/repositories/knowledge.py` 支持两类新风险规则的存取，在 `backend/sample_data/knowledge_seed.json` 补带来源的样例。
4. 在团队的**系统测试 Word 文档**写并执行药箱编辑、组合风险、知识库管理、服药记录及儿童补录的用例，把实测记录交给 sjw。
