# 药明白前端联调清单

本地联调走 Vite 的 `/api` 代理。家庭端在 `/`，知识库管理端在 `/admin`。接口提交与保存以服务端响应为准，失败保留输入。以下接口路径包含 `/api` 前缀。

## 当前可对接

| 流程 | 当前接口及前端行为 |
| --- | --- |
| 识别与核对 | 图片在浏览器用 Tesseract.js 识别，首次需下载识别资源。用户可修改原文，随后向 `POST /api/instruction/parse` 发送 `ocr_text`，或单独发送 `sample_id`。也可直接填写核对表。 |
| 检查后入箱 | `GET /api/members` 提供成员列表。选中成员后，将 `member_id`、`candidate_name`、`candidate_ingredients` 提交给 `POST /api/interactions/check`。前端展示 `items`、`count`、`message`、`missing`；命中风险需另勾选知晓。 |
| 保存及回查 | `POST /api/medicines` 使用现有 `owner` 成员名称和核对后的药名、成分数组、用量、频次，发送 `confirmed: true` 及 `risk_accepted`。201 后可回药箱，409 会清除旧风险报告，其他失败保留表单。 |
| 库存与位置 | `PUT /api/medicines/{id}` 接收现有药品字段和修改项。当前仅开放库存与位置编辑；保存后服务端重置核对状态。药箱显示已过有效期和明确为零的库存。 |
| 儿童记录 | `POST /api/records` 的 `temperature` 是字符串。网页提交实际记录人、用量、可选体温及备注，按服务端时间保存。 |
| 知识发布与查询 | 管理端保存草稿、审核发布和停用。家庭端知识查询和药品成分匹配使用已发布资料。 |

## 跨包待确认

| 事项 | 对接责任 | 要确认的输入输出或验收行为 |
| --- | --- | --- |
| 药品重新核对与编辑 | sjw、qhy、wzy | 确认哪些改动需要重新核对。库存及位置修改是否保留原核对状态。药名、成分或使用者变化后，检查新组合时应排除当前药品，并保存风险确认和最终核对状态。 |
| 药品与成员关联 | sjw、qhy、wzy | 现有新增和筛选按 `owner` 名称，风险检查按 `member_id`。如迁移到 ID，统一请求及响应字段、历史数据迁移和同名成员场景。 |
| 到点通知 | sjw、qhy | 当前提醒设置、今日列表与确认可用。确认业务时区、触发时间、去重和后台通知方式，再联调页面提示与系统通知。 |
| 儿童历史补录 | sjw、qhy、wzy | 确认实际服药时间的字段、时区、允许范围及与创建时间的区别。现有创建请求没有 `taken_at`。 |
| 风险规则扩展 | qhy、wzy | 确认食物饮品及特殊人群规则的资料来源、匹配条件、结果结构和测试数据。前端沿用已发布依据展示。 |
| AI 真实联调 | qhy、wmx | 提供课程演示可用的服务及模型配置，验证回答、引用、追问和异常提示。 |
| 多家庭隔离 | sjw、qhy、wzy | 若验收保留，确定家庭身份、数据归属及跨家庭访问失败响应。当前使用本地演示家庭。 |

## 验收顺序

1. 用人工填写或识别文字填写核对表，选择成员，检查风险并确认，回药箱验证保存结果。
2. 修改药品核对字段后，确认之前的风险结果和勾选状态失效。使用有匹配规则的已发布资料，验证风险确认和放弃入箱。
3. 修改库存和位置，核对药箱提示、刷新后数据及老人模式核对状态。
4. 管理端建草稿、发布、停用，检查家庭端知识检索结果是否随之变化。
