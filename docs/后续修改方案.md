# 药明白项目后续修改方案

## 1. 项目目标

将现有 SwiftUI + FastAPI 的“药明白”原型，逐步调整为：

> Vue 3 前端 + FastAPI 后端 + OCR 识别 + 用药知识库 + 规则引擎的家庭用药管理与安全辅助系统。

本阶段不接入大模型。系统通过 OCR、结构化数据、可审核的知识库和确定性规则完成药品识别、药箱管理、相互作用风险提示、提醒和服药记录。

产品只用于说明书整理、知识查询、风险提示、用药提醒和记录，不提供疾病诊断、处方、药品推荐，也不自动决定停药、换药或调整剂量。

## 2. 最终用户流程

```text
拍摄药盒或说明书
    ↓
OCR识别图片文字
    ↓
规则解析药品字段
    ↓
用户核对并补充信息
    ↓
匹配标准通用名和有效成分
    ↓
选择家庭成员并加入药箱
    ↓
检查与该成员现有药品的潜在相互作用
    ↓
查看风险等级、说明书依据和安全建议
    ↓
设置提醒、确认服药并形成记录
```

## 3. 技术架构调整

### 3.1 前端

- 使用 Vue 3、TypeScript、Vite。
- 使用 Vue Router 管理页面路由。
- 使用 Pinia 管理家庭成员、药品、提醒、记录和风险状态。
- 使用 Vant 或 Element Plus 统一移动端交互。
- 使用 PWA 支持手机浏览器安装和基础离线缓存。
- 使用 Tesseract.js 作为初期浏览器 OCR 方案；稳定后可切换为 FastAPI + PaddleOCR。

### 3.2 后端

继续使用 FastAPI 和现有 SQLite，保留已有成员、药品、提醒、记录、今日状态和说明书解析接口。

新增模块：

```text
backend/
├── knowledge/
│   ├── normalization.py       # 商品名、别名、通用名和成分标准化
│   ├── interaction_checker.py # 相互作用规则匹配
│   ├── repository.py          # 知识库查询
│   └── source_manager.py      # 来源和版本管理
├── routers/
│   ├── knowledge.py           # 知识查询接口
│   └── interactions.py        # 风险检查接口
└── sample_data/
    └── knowledge/             # 课程演示知识库
```

### 3.3 数据流原则

- OCR 信息、用户确认信息、知识库信息分开保存。
- OCR 结果不能未经确认直接加入药箱。
- 相互作用判断只使用标准化药品成分和已审核规则。
- 没有命中规则时显示“暂未发现已收录风险”，不显示“绝对安全”。
- 所有风险提示都关联来源、章节、版本和更新时间。

### 4.2 OCR 与说明书解析

新增图片识别流程：

1. Vue 调用摄像头或相册选择图片。
2. OCR 得到原始文字。
3. 前端展示原始文字，允许用户修正。
4. 调用现有 `/api/instruction/parse`。
5. 展示结构化药品卡片。
6. 对缺少药名、剂量、频次等关键字段的结果提示人工核对。

后端可新增：

```text
POST /api/instruction/recognize
```

该接口用于后端 PaddleOCR 方案，返回 `ocr_text` 和识别质量；初期也可以先由前端 OCR 后直接调用已有解析接口。

### 4.3 药品标准化

识别到商品名或别名后，匹配知识库中的标准通用名和有效成分。

匹配结果必须允许用户确认：

```text
识别名称：芬必得
标准通用名：布洛芬缓释胶囊
主要成分：布洛芬
匹配状态：待确认
```

无法确定时保留原始名称，并提示用户手动搜索或录入，不强行匹配。

### 4.4 用药知识库

知识库首版建议收录 20～50 种常见药品，使用人工整理和审核的数据，避免一开始爬取大量未经授权的网络内容。

知识内容包括：

- 药品通用名、商品名、别名和有效成分。
- 用法用量、禁忌和注意事项。
- 老人、儿童、孕妇、哺乳期及过敏人群提示。
- 药物与药物的相互作用。
- 药物与酒精、葡萄柚、牛奶等食物或饮品的注意事项。
- 说明书来源、章节、版本、审核状态和更新时间。

优先采用国家药监部门公开信息、药品批准说明书和国家卫生健康相关规范；每条知识都必须保留来源。

### 4.5 相互作用风险检查

风险检查触发时机：

- 新药加入某位成员药箱前。
- 药品删除、修改使用者或切换在用状态后。
- 用户在药箱页面主动点击“风险扫描”。
- 知识库规则更新后重新检查。

检查过程：

```text
读取成员在用药品
→ 转换为标准通用名/有效成分
→ 两两匹配相互作用规则
→ 合并重复结果
→ 按最高风险等级排序
→ 展示风险、建议和来源
```

风险等级建议使用：

- 严重风险：建议尽快咨询医生或药师。
- 需关注：可能需要监测或错开使用，按来源建议处理。
- 一般提醒：注意服药时间、食物或常见影响。
- 数据不足：当前资料不足，不能作出判断。

风险提示允许用户“暂不加入”或“知晓风险后继续加入”，但必须记录确认状态。

## 5. 建议新增接口

```text
POST /api/instruction/recognize
GET  /api/knowledge/drugs?keyword=...
GET  /api/knowledge/drugs/{id}
GET  /api/knowledge/drugs/{id}/sources
POST /api/interactions/check
```

```json
{
  "member_id": 2,
  "medicine_ids": [4, 7, 12]
```

```json
  "risk_level": "high",

      "drugs": ["布洛芬", "华法林"],
      "severity": "high",

      "source_title": "药品说明书",
      "source_section": "药物相互作用",
      "evidence_text": "说明书原文"
    }
  ]
}
```

## 7. 前端页面规划

底部导航建议保留四项：


- `ScanView.vue`：拍照、OCR、原文检查和药品卡片确认。
- `DrugKnowledgeView.vue`：按药品名、通用名或成分查询知识。
- `RiskReportView.vue`：展示成员药箱风险报告、依据和来源。
- `InteractionDetail.vue`：展示两种药的风险关系和标准建议。


## 8. 测试和验收

### 8.1 单元测试

- 商品名、别名到通用名的匹配。
- 复方药有效成分拆分。
- 药物相互作用的双向匹配。
- 同一风险规则去重。
- 风险等级排序。
- 无匹配结果的提示文案。
- 知识库来源缺失时的异常处理。

### 8.2 接口测试

- 图片识别成功、失败和空文字。
- 药品加入前的风险检查。
- 不存在的成员或药品返回明确错误。
- 风险确认状态正确保存。
- 删除和停用药品后风险报告更新。

### 8.3 用户验收场景

1. 用户拍摄说明书，成功得到结构化药品卡片。
2. 识别字段缺失时，用户可以手动修改后再保存。
3. 新药加入已有药箱时，系统能展示相互作用依据。
4. 没有命中规则时，系统不会显示“绝对安全”。
5. 用户可以查看风险说明书原文和来源版本。
6. 老人模式能够用大字号完成查看和确认服药。
7. 服药提醒和历史记录不受风险检查模块影响。

## 11. 最终演示闭环

```text
拍摄布洛芬说明书
→ OCR识别并提取用法、禁忌和注意事项
→ 用户确认药品和有效成分
→ 选择爷爷并加入药箱
→ 与爷爷已有药品进行组合检查
→ 展示风险等级、说明书原文和安全建议
→ 用户确认后设置提醒
→ 确认服药并查看历史记录
```

项目的核心创新表述为：

> 以家庭成员为中心，将药品识别、说明书核对、知识库检索、组合用药风险提示、提醒和服药记录串成一个可追溯的家庭用药安全闭环；风险结论来自可审核、可测试的规则和知识来源，不依赖不可解释的自动生成。
