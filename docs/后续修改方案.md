# 基于智能识别与用药知识辅助的家庭药箱系统——药明白

## 1. 项目目标

“药明白”面向老人、儿童家长、长期服药者和家庭照护者，建设家庭用药管理与安全辅助系统。系统通过 OCR、说明书规则解析、用药知识库和相互作用规则，完成药品识别、说明书核对、家庭药箱管理、风险提示、服药提醒和记录。

本阶段不接入大模型。风险结论来自可审核、可测试的知识库和确定性规则；系统只提供信息整理、知识查询和风险提示，不提供疾病诊断、处方、药品推荐，也不自动决定停药、换药或调整剂量。

## 2. 用户使用流程

```text
拍摄药盒或说明书 → OCR识别图片文字 → 规则解析药品信息
→ 用户核对并补充 → 匹配通用名和有效成分 → 选择成员加入药箱
→ 检查该成员现有药品风险 → 查看依据和建议 → 设置提醒并记录服药
```

## 3. 技术方案

### 3.1 Vue 前端

- 使用 Vue 3、TypeScript 和 Vite 重建原 SwiftUI 客户端。
- 使用 Vue Router 管理识别、药箱、提醒、记录和知识查询页面。
- 使用 Pinia 管理家庭成员、药品、提醒、服药记录和风险报告状态。
- 使用 Vant 或 Element Plus 统一移动端组件。
- 初期使用 Tesseract.js 完成浏览器 OCR；后续可切换为 FastAPI + PaddleOCR。

### 3.2 FastAPI 后端

继续保留已有成员、药品、提醒、服药记录、今日状态和说明书解析接口。新增 `knowledge` 模块，负责名称标准化、知识查询、来源管理和相互作用规则匹配。

### 3.3 数据原则

- OCR 信息、用户确认信息和知识库信息分开保存。
- OCR 结果未经用户确认不能直接加入药箱。
- 相互作用判断基于标准通用名或有效成分。
- 没有命中规则时显示“暂未发现已收录风险”，不能显示“绝对安全”。
- 每条风险提示关联来源、说明书章节、版本和更新时间。

## 4. 核心功能

### 4.1 智能识别与说明书解析

用户通过摄像头或相册上传药盒、标签或说明书图片。系统识别原始文字并允许修正，再提取药名、规格、一次用量、服用频次、服用方式、服用时间、贮藏方式、有效期、禁忌和注意事项。关键字段缺失时提示重新拍摄或手动补充。

现有 `/api/instruction/parse` 继续用于文字解析；后续可增加 `POST /api/instruction/recognize` 返回 OCR 原文和识别质量。

### 4.2 药品名称标准化

系统将商品名或别名匹配为标准通用名和有效成分，例如“芬必得 → 布洛芬缓释胶囊 → 布洛芬”。匹配结果必须由用户确认；无法确定时保留原始名称并提示手动搜索。

### 4.3 用药知识库

首版人工整理并审核 20～50 种常见药品，内容包括：通用名、商品名、别名、有效成分、用法用量、禁忌、注意事项、特殊人群提示、药物相互作用、食物或饮品注意事项，以及来源机构、章节、版本、审核状态和更新时间。

优先使用国家药监部门公开信息、药品批准说明书和国家卫生健康相关规范。每条知识必须保存来源。

### 4.4 相互作用风险检查

新药加入成员药箱前、药品删除或修改使用者后、用户主动扫描时，以及知识库规则更新后，系统都应重新检查。

```text
读取成员在用药品 → 转换为通用名/有效成分 → 两两匹配规则
→ 合并重复结果并按最高等级排序 → 展示风险、建议和来源
```

风险等级分为严重风险、需关注、一般提醒、数据不足。高风险仅建议咨询医生或药师，不要求用户自行停药或调整剂量。用户可暂不加入，也可知晓风险后继续加入，系统保存确认状态。

## 5. 建议新增接口

```text
POST /api/instruction/recognize
GET  /api/knowledge/drugs?keyword=...
GET  /api/knowledge/drugs/{id}
GET  /api/knowledge/drugs/{id}/sources
POST /api/interactions/check
GET  /api/members/{id}/risk-report
POST /api/knowledge/feedback
```

风险检查结果至少包含涉及药品、风险等级、可能影响、标准行动建议、来源标题、说明书章节和原文依据。

## 6. 数据库调整

在现有数据库基础上新增：

```text
drug_aliases           # 商品名、别名和通用名映射
drug_ingredients       # 药品与有效成分
knowledge_sources      # 来源、机构、版本和审核状态
drug_interactions      # 药物与药物相互作用规则
food_interactions      # 药物与食物或饮品规则
risk_confirmations     # 用户风险确认记录
```

相互作用规则至少保存双方成分、风险等级、可能影响、行动建议、说明书原文和来源编号。

## 7. Vue 页面规划

底部导航保留“首页｜家庭药箱｜提醒记录｜我的”。

- `ScanView.vue`：拍照、OCR、原文检查和药品卡片确认。
- `MedicineBoxView.vue`：查看成员药品、库存、有效期和风险数量。
- `DrugKnowledgeView.vue`：按药品名、通用名或成分查询知识。
- `RiskReportView.vue`：展示风险报告、标准建议和来源。
- `InteractionDetail.vue`：展示两种药的关系和说明书原文。
- `ReminderView.vue`：显示提醒及与本次服药相关的简短提示。
- `RecordsView.vue`：查询服药和儿童喂药历史。
- `ElderMode.vue`：提供大字号、高对比度和语音播报。

家庭药箱首页显示当前成员、在用药品数量、最高风险等级、风险数量和资料待核对数量，并提供“立即扫描用药风险”入口。

## 8. 测试与验收

### 8.1 规则和知识库测试

- 商品名、别名到通用名的匹配。
- 复方药有效成分拆分。
- 相互作用规则双向匹配、去重和等级排序。
- 无匹配结果、来源缺失、版本过期和规则停用的处理。

### 8.2 接口和流程测试

- OCR 成功、失败和空文字。
- 关键字段缺失时不能直接保存。
- 新药加入前风险检查。
- 不存在成员或药品时返回明确错误。
- 风险确认、删除、停用和修改药品后报告正确更新。

### 8.3 用户验收场景

1. 用户拍摄说明书并得到结构化药品卡片。
2. 用户能修改识别结果并确认有效成分。
3. 新药加入已有药箱时展示相互作用和依据。
4. 未命中规则时不显示“绝对安全”。
5. 用户能查看风险来源、说明书章节和更新时间。
6. 老人能用大字号完成查看和确认服药。
7. 提醒、服药记录和儿童喂药记录正常工作。

## 9. 最终演示闭环

```text
拍摄布洛芬说明书 → OCR识别并提取用法、禁忌和注意事项
→ 用户确认药品和有效成分 → 选择爷爷并加入药箱
→ 与爷爷已有药品进行组合检查 → 展示风险等级、原文和建议
→ 用户确认后设置提醒 → 确认服药并查看历史记录
```

项目创新点：以家庭成员为中心，将智能识别、说明书核对、用药知识辅助、组合用药风险提示、提醒和服药记录串成可追溯的家庭药箱闭环；风险信息来自可审核、可测试的知识库和规则。
